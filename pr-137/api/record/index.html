    Record¶

    Record dataclass ¶

    Record(
    revision_id: UUID,
    sources: list[LayerSource],
    workspace: Workspace,
)

    A record's layers folded last-writer-wins, read as DuckDB relations.

    One class for every backing, because a fold over one source degenerates to a scan of it - so a plain parquet directory is read as the one layer it is (Workspace.at) rather than by a second code path. RecordLike is the protocol a caller annotates against; this is the class a caller holds.

    Nothing up to the last frozen source can go stale, so the fold over them is kept in shared tables. A source after it is folded onto those tables per read, so a staged edit reads back with nothing to invalidate. The record holds those tables from construction until close(), or until it and every relation taken from it are collected.

    Parameters:

    Name Type Description Default
    revision_id UUID

    The node whose frozen layers are folded, which names the shared tables their fold is kept in.

    		 required
    sources list of LayerSource

    Root first, ending in the layer being resolved, truncated at the deepest materialised ancestor (sources_to_read). A WorkingRecord's staged rows are one more source on the end.

    		 required
    workspace Workspace

    Where the calling thread's cursor comes from.

    		 required

    Raises:

    Type Description
    ValueError

    On a read once the record is closed.
    Notes
    • the Record protocol
    • a layer's data is write-once
    • materialised node caches
    • the owner map
    • reading with pending edits
    • the database's schemas

    def register(self, name: str) -> None:
    """Create the schema `name` with a view per dim, property subject and attribute.

    The views sit in `name.dims`, `name.properties` and `name.attributes` of
    the workspace's database, as in `datarecord.name.dims.bus`, each reading as
    its relation here; over a `WorkingRecord` they follow every edit. They hold
    the tables the record reads, its folds and a `WorkingRecord`'s staging
    tables, until `unregister(name)`, whether the record is closed or not.
    `name` is listed in `Workspace.registered()`.

    Raises
    ------
    duckdb.CatalogException
        If the schema `name` exists in the workspace's database, as
        `_fold` and `_staged` always do.
    duckdb.TransactionException
        Where the cursor already holds an open transaction, or another
        cursor registers `name` at the same time.

    Notes
    -----
    - [registered views](https://energy-models.github.io/datarecord/design/storage/views/)
    """
    ws = self.workspace
    kinds = {
        "dims": self.dims,
        "properties": self.properties,
        "attributes": self.attributes,
    }
    rendered = {
        (ws.name, name, kind, view): _render(rel, literals=True, wrap_text=True)[0]
        for kind, relations in kinds.items()
        for view, rel in relations.items()
    }
    con = self.con
    holds = ws._holds
    with transaction(
        con,
        "register",
        "https://energy-models.github.io/datarecord/design/storage/views/",
    ) as on_rollback:
        con.execute(f"CREATE SCHEMA {col(ws.name, name)}")
        holds.hold(name, self._kept_schemas)
        on_rollback(partial(holds.release, name))
        for kind in kinds:
            con.execute(f"CREATE SCHEMA {col(ws.name, name, kind)}")
        for path, query in rendered.items():
            con._create_view(path, query)
        con.execute(
            f"INSERT INTO {ws.qualified('registered')} (name, revision, working, held)"
            " VALUES (?, ?, ?, ?)",
            [
                name,
                self.revision_id,
                not self.frozen,
                sorted(self._kept_schemas),
            ],
        )

    def select(record: RecordLike, /, **labels: Any) -> Selection:
    """`record` at the labels named, as xarray's `sel` takes them.

    A keyword names a dim; one naming a multi-dim's coordinate that is no dim
    narrows its tuples, and any other names a property by its bare name and
    narrows its subject to the labels whose value, its default applied, is
    selected. One label squeezes its dim. A list, a slice (both ends
    inclusive, `None` open) or a partial date string on a datetime axis keeps
    it. Every label referring to a dropped one goes with it, through
    properties and multi-dim tuples, until nothing more goes. Over a
    `Selection`, its keywords are merged and its base selected.

    Returns
    -------
    Selection
        The view, which reads the axes it matched and propagated on as they
        were at the call, and plans every attribute on the base's connection.

    Raises
    ------
    ValueError
        Naming the keyword: one naming no dim, coordinate or property, a
        multi-dim, a coordinate of several multi-dims or a property several
        subjects declare; a label the axis lacks; an empty list; a slice with
        a step, of an axis neither numeric nor datetime, with an end the axis
        cannot compare or covering no label; a squeezed label another
        keyword's selection drops; a squeeze folding a category into the
        default a kept label NULL on it does not take; squeezing every dim of
        a record with attributes.

    Notes
    -----
    - [selecting](https://energy-models.github.io/datarecord/design/use/selecting/)
    - [what goes with a dropped label](https://energy-models.github.io/datarecord/design/use/selecting/#what-goes-with-a-dropped-label)
    """
    if isinstance(record, Selection):
        return record.select(**labels)
    schema = record.schema
    read = _Read(record)
    asked: dict[str, Any] = {}
    squeezed: dict[str, Any] = {}
    kept: dict[str, set[Any]] = {}
    for keyword, value in labels.items():
        if keyword in schema.multi_dims:
            raise _refusal(
                keyword,
                value,
                "names a multi-dim, whose tuples are selected through its coordinates",
            )
        if keyword in schema.dimensions:
            matched = _match(
                keyword, value, read.axis(keyword), _dtype(schema, keyword)
            )
            asked[keyword] = matched
            if not isinstance(matched, list):
                squeezed[keyword] = matched
            _narrow(kept, keyword, {_key(m) for m in _listed(matched)})
            continue
        subject, allowed, asked[keyword] = _narrowing(schema, read, keyword, value)
        _narrow(kept, subject, allowed)
    for m in schema.multi_dims:
        over = schema.over(m)
        if all(d in squeezed for d in over.values()):
            squeezed[m] = {c: squeezed[d] for c, d in over.items()}
            _narrow(kept, m, {_key(t) for t in read.axis(m)})
    if schema.attributes and schema.dimensions.keys() <= squeezed.keys():
        raise _refused(
            {k: v for k, v in asked.items() if k in squeezed},
            "squeezes every dim, and attributes over no axis are no record; "
            "keep one dim as a list of one",
        )
    _propagate(schema, read, kept)
    for keyword, label in asked.items():
        if keyword in squeezed and _key(label) not in kept[keyword]:
            raise _refusal(
                keyword,
                label,
                "is squeezed at a label the selection drops through another keyword",
            )
    _refuse_uncategorized(schema, read, squeezed, kept)
    narrowed = {
        d: numbered_relation(
            record.con,
            d,
            [label for label in read.axis(d) if _key(label) in keys],
            _dtype(schema, d),
            _AT,
        )
        for d, keys in kept.items()
        if d in squeezed or len(keys) < len(read.axis(d))
    }
    view = _schema(schema, squeezed, read.category(squeezed))
    return Selection(record, asked, view, squeezed, narrowed)

    def lift(self, attribute: str, rel: DuckDBPyRelation) -> DuckDBPyRelation:
    """`rel`, rows of `attribute` over this view, with the squeezed labels put back.

    Each squeezed dim the base declares `attribute` over is added as a
    column at its label, and each squeezed coordinate back into its
    multi-dim's struct; a NULL struct stays NULL. An attribute the base
    declares over no squeezed dim comes back as it came.

    Raises
    ------
    KeyError
        If the base declares no `attribute`.

    Notes
    -----
    - [lifting rows back](https://energy-models.github.io/datarecord/design/use/selecting/#lifting-rows-back-to-the-base)
    """
    base = self.base.schema
    coordinates = base.coordinates_of(attribute)
    changed = [
        c
        for c in coordinates
        if c in self._squeezed or (c in rel.columns and self._shrunk(c))
    ]
    if not changed:
        return rel
    lifted: list[Expression] = []
    for c in coordinates:
        if c in self._squeezed:
            lifted.append(_literal(self._squeezed[c], self._type(c)).alias(c))
        elif c in changed:
            fields = {
                f: col(c)[f]
                if f in self.schema.over(c)
                else _literal(self._squeezed[d], self._type(d))
                for f, d in base.over(c).items()
            }
            lifted.append(_tuple(c, fields, self._type(c)))
        elif c in rel.columns:
            lifted.append(col(c))
    rest = [col(c) for c in rel.columns if c not in coordinates]
    return rel.project(*lifted, *rest)
